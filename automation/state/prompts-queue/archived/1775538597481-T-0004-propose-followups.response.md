# T-0004 Proposed Follow-up Tasks

## Overview
After T-0004 implementation, these follow-up tasks enhance gameplay and address deferred concerns. Tasks are listed in priority order.

## Follow-up tasks

### T-0004-A: Debug collision direction detection (Priority: Critical)
- **Goal**: Verify top vs. side collision disambiguation works correctly in edge cases
- **Context**: T-0004 uses velocity.y sign to detect collision direction; diagonal collisions may be ambiguous
- **Work**: Test with walkers moving horizontally while player approaches from multiple angles; verify no false "side kills" from top-landing
- **Owner**: codex (implementation debug)
- **Depends on**: T-0004 (implementation complete)

### T-0004-B: Performance profiling and entity limit enforcement (Priority: High)
- **Goal**: Measure frame rate with max 8 concurrent entities; identify bottlenecks
- **Context**: Spec targets max 8 dynamic entities; no profiling done yet
- **Work**: Create test level with 8 walkers, 4 moving platforms; measure frame time; optimize AABB collision if needed; document entity budget per level
- **Owner**: codex (testing)
- **Depends on**: T-0004 (implementation complete)

### T-0004-C: Level design documentation and tilemap templates (Priority: High)
- **Goal**: Document tilemap encoding format; provide example levels
- **Context**: Brief specifies spike (2), crumble (3), patrol-h (4), patrol-v (5) but no concrete tilemap example exists
- **Work**: Create tilemap format guide (JSON or pseudo-code); design 2-3 tutorial levels demonstrating each obstacle type; publish in docs/LEVELS.md
- **Owner**: codex (docs)
- **Depends on**: T-0004 (implementation complete)

### T-0004-D: Extend collision to support sloped platforms (Priority: Medium)
- **Goal**: Add physics for angled platforms (e.g., ramps)
- **Context**: Current implementation assumes rectangular AABBs; slopes require different collision math
- **Work**: Implement AABB-to-line collision for slope detection; allow player to walk up/down slopes with correct velocity adjustment
- **Owner**: codex (enhancement)
- **Depends on**: T-0004 (implementation complete), T-0003 (collision system)

### T-0004-E: Add invincibility frames on enemy bounce (Priority: Medium)
- **Goal**: Prevent player death from landing in multiple enemies sequentially
- **Context**: T-0004 bounces player but no grace period; player could land on second enemy immediately
- **Work**: Add `gameState.invulnerableFrames` counter; skip enemy collision checks while counter > 0; decrement each frame
- **Owner**: codex (enhancement)
- **Depends on**: T-0004 (implementation complete)
