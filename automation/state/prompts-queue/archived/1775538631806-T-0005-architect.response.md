# T-0005 Spec

## Task metadata
- Task ID: T-0005
- Title: Implement collectibles, rewards, and power-ups
- Lane: feature-lane
- Executor: codex (ChatGPT)
- Depends on: T-0003 (collision system), T-0004 (obstacles/enemies, optional for level density)

## Problem statement
The game currently has no reward or progression system. To make gameplay engaging, we need:
1. Collectible coins (abundant, +10 XP each) scattered throughout levels
2. Rare gems (scarce, +50 XP) hidden or placed at difficult-to-reach locations
3. Temporary power-ups: speed boost (1.5x movement speed), shield (absorb one hit), magnet (attract coins from distance)
4. Visual feedback on collection (pickup animation: scale + fade)
5. Persistent tracking of coins collected per run (for HUD display in T-0007)

## Source of truth
- CONFIG: CANVAS_WIDTH:800, CANVAS_HEIGHT:400, TILE_SIZE:16, GRAVITY:0.6
- Single-file implementation: index.html
- Collision system from T-0003
- Existing gameState structure
- XP system (introduced in T-0006, but collectibles define XP values)

## Desired behavior

### Coins
- Size: 1x1 tile (16x16px), rotating sprite (simple 2-frame rotation animation)
- Spawn: scattered throughout level via tilemap or inline objects
- Value: +10 XP on collection
- Animation: on pickup, coin scales to 1.5x then fades over 0.3s
- Persist: collected coins removed from tilemap permanently (stored in level state)
- Visual: distinct gold/yellow color

### Gems
- Size: 1x1 tile (16x16px), sparkling sprite (4-frame animation)
- Spawn: rare placement via tilemap metadata (e.g., 5-10 per level)
- Value: +50 XP on collection
- Animation: on pickup, gem scales to 1.5x then fades over 0.3s; emit 3-5 particle sparks
- Persist: collected gems removed permanently
- Visual: distinct blue or purple color

### Power-ups (generic pickupable)
- Size: 1x2 tiles (16x32px) for visibility
- Spawn: limited quantity (1-3 per level), placed at notable positions
- Duration: 8 seconds (or until player dies)
- Animation: floating up/down gently while on ground; on pickup, icon scales and fades
- Persist: power-up removed after pickup; respawns on level restart

#### Speed Boost
- Visual: orange/red sprite with directional arrow
- Effect: player velocity.x multiplier = 1.5x; jump velocity unchanged
- UI indicator: "Speed Boost 8s" in HUD
- Wear off: visual fade as timer approaches 0

#### Shield
- Visual: blue/cyan sprite with shield icon
- Effect: next hit (spike, enemy, obstacle) is absorbed; shield disappears; player continues
- UI indicator: shield icon in HUD
- Wear off: expires on level restart; can be hit once per pickup

#### Magnet
- Visual: purple/magenta sprite with magnetic field icon
- Effect: all coins within 5 tiles (80px) automatically move toward player at 3 tiles/sec
- UI indicator: "Magnet 8s" in HUD; visual aura around player
- Wear off: coins stop moving toward player

### Collision detection
- Extend T-0003 collision to detect player-collectible overlap (no AABB, simple center distance check)
- Distance threshold: 1 tile (16px) for automatic pickup
- Pickup callback: add XP, remove collectible, apply power-up if applicable

### Persistence
- Track collected coins in level state: `gameState.levelCoins = { collected: 5, total: 20 }`
- Power-ups active: `gameState.activePowerUps = [{ type: "shield", expiresAt: frameCount }]`
- Per-run total: sum all coins/gems collected across level (HUD in T-0007)

## Constraints
- Single-file HTML implementation (no bundler)
- Max 50 collectibles per level (scalability target)
- Pickup detection must run at 60 FPS
- Animations must be frame-based
- All sprites are 16x16 or 16x32 (multiples of TILE_SIZE)
- Power-ups use frame counters, not timers (frame-based expiry: expiresAt = gameState.frameCounter + 480 for 8 seconds at 60 FPS)
- Magnet pulls coins in straight line, no pathfinding
- Collectibles defined in tilemap or inline objects; no procedural generation

## Acceptance criteria
1. Coins spawn at tilemap positions, visible, rotatable sprite
2. Coins collected on player overlap (distance < 16px), value +10 XP added to gameState
3. Gem spawns at tilemap positions, value +50 XP, sparkle animation on pickup
4. On pickup, collectible plays scale+fade animation (0.3s), then disappears
5. Speed boost active: player.velocity.x *= 1.5 for all directional inputs, duration 8s
6. Shield active: next obstacle/enemy collision absorbed, shield removed, player safe
7. Magnet active: coins within 5 tiles move toward player at 3 tiles/sec, stop when picked up or magnet expires
8. Power-up UI shows type and remaining time (in HUD, T-0007)
9. Power-ups expire after 8s or on player death/respawn
10. Collected coins tracked in gameState.levelCoins for persistence per level

## Risks
1. **Collectible vs. collision order** - If coin is collected same frame as spike hit, which happens first? Mitigation: process collectibles before obstacles (coins picked up, then spike checked).
2. **Magnet performance** - With 50 coins and magnet active, must update position for each coin every frame. Mitigation: use simple distance check (avoid expensive pathfinding), optimize by culling coins off-screen.
3. **Power-up overlap** - If player picks up speed boost and shield simultaneously, which applies? Mitigation: pick up all overlapping power-ups (stack them in gameState.activePowerUps array).
4. **Collectible respawn** - Do coins respawn on level restart, or stay collected? Mitigation: reset gameState.levelCoins on level start; collectibles always respawn fresh.
5. **Magnet coin direction** - Coins move in straight line to player; what if walls block path? Mitigation: no collision check; coins pass through obstacles (they're not physical in magnet mode, just visual).

## Open questions
1. Should coins respawn on death/level restart, or persist permanently? (Assumption: respawn fresh each level)
2. Do power-ups stack (multiple shields, multiple speed boosts), or replace each other? (Assumption: stack in array, both active)
3. What happens if player dies while magnet is active? (Assumption: magnet expires; coins stop moving toward player)
4. Can coins be collected mid-air, or only on platforms? (Assumption: no restriction; collectibles are frictionless)
5. Should magnet show a visual connection line to coins, or just move them? (Assumption: move silently, no visual line)
