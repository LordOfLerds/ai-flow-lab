# T-0007 Spec

## Task metadata
- Task ID: T-0007
- Title: Add HUD, score tracking, game over, menus, and polish
- Lane: feature-lane
- Executor: codex (ChatGPT)
- Depends on: T-0001 (canvas rendering), T-0002 (player), T-0004 (obstacles/enemies), T-0005 (collectibles), T-0006 (progression)

## Problem statement
The game currently has functional gameplay but lacks UI, polish, and state management. To create a complete player experience, we need:
1. Heads-up display (HUD) showing real-time game state (score, coins, XP, level, active power-ups)
2. Game-over screen with summary (final score, XP earned, restart button)
3. Start screen with title, play button, and skin selector
4. Visual polish (screen shake on key events, particle effects, smooth transitions)
5. Gameplay progression (scrolling speed increases over time)

## Source of truth
- CONFIG: CANVAS_WIDTH:800, CANVAS_HEIGHT:400, TILE_SIZE:16, GRAVITY:0.6
- Single-file implementation: index.html
- Game state from prior tasks (T-0001 through T-0006)
- Player, obstacles, collectibles, XP, skills, skins all exist

## Desired behavior

### HUD (in-game overlay)
- Position: top-left corner, semi-transparent background
- Display elements (update every frame):
  - "Score: X" (total coins collected this level)
  - "Coins: X / Y" (coins collected / total coins in level)
  - "XP: X / Y" (current XP / next level threshold)
  - "Level: Z"
  - "Skin: [current skin name]"
  - Active power-ups list with timer (e.g., "Speed Boost 3.2s", "Shield 0.1s")
  - Skills active (e.g., "Double Jump: ON", "Dash: ON", "Shield Start: ON")
- Font: simple monospace, white text, black outline for readability
- Update rate: 60 FPS (synchronized with game loop)

### Game-over screen
- Triggered when player dies (spike, enemy side collision, falls off-screen)
- Overlay: semi-transparent dark background covering entire canvas
- Text (centered):
  - "GAME OVER"
  - "Final Score: X coins"
  - "XP Earned: Y points"
  - "Level Reached: Z"
  - "Coins Collected: X / [level total]"
- Buttons:
  - "Restart Level" (restart same level, reset position)
  - "Back to Menu" (return to character select menu)
  - "Next Level" (if all goals reached, unlock this button; skip to next level)
- Persist for 3 seconds before allowing input (no accidental clicks)
- Display stats for 0.5s before player can interact

### Start screen
- First screen shown on game load
- Overlay: canvas-filling semi-transparent dark background
- Title: "PLATFORMER" (large, centered, at top)
- Subtitle: "Collect coins, avoid obstacles, master skills" (smaller, centered, below title)
- Buttons (centered, vertically stacked):
  - "Play" (start game; transitions to character select menu)
  - "Credits" (show simple credits overlay; "Game Design: [team]", "Assets: [team]")
  - "Settings" (show settings menu; sound toggle, difficulty selector; deferred)
- Decorative: optional starfield or subtle animation in background

### Character select menu
- Shown after pressing "Play" on start screen
- Display: list of unlocked skins with thumbnails; allow selection
- Show player level, total XP, unlocked skills
- "Start Level 1" button to begin game
- "Back" button to return to start screen

### Transitions and polish
- **Screen shake** - On enemy death (jump on head): 2-frame jitter (±3 pixels) in both x/y
- **Particle effects**:
  - Coin pickup: 5-8 small sparks burst outward from pickup point over 0.3s, fade
  - Gem pickup: 8-12 larger sparkles with slower fade (0.5s)
  - Enemy death: brief puff of dust at kill location (3-5 particles, white/gray)
- **Menu transitions** - Fade to black (0.3s) between screens; fade in to new screen (0.3s)
- **Smooth state changes** - HUD updates smoothly on level-up, power-up pickup, skill unlock (no flickering)

### Speed progression
- Base scroll speed starts at 1x (no scrolling)
- After 30 seconds: speed ramps to 1.2x
- After 60 seconds: speed ramps to 1.5x
- After 120 seconds: speed ramps to 2.0x
- Formula: `scrollSpeed = 1.0 + (elapsedSeconds / 120) * 1.0` (caps at 2x after 120 seconds)
- Scrolling applies to entire level (all platforms, obstacles, collectibles move with camera)
- Player position relative to screen stays same (camera follows)

## Constraints
- Single-file HTML implementation (no bundler)
- HUD renders on top of game (canvas layer, no DOM)
- Game-over screen must wait 3s before accepting input (prevent accidental restarts)
- All text uses canvas drawText (no DOM text elements)
- Particles are simple sprites (small circles or squares) with alpha fade
- Screen shake uses frame-based randomization (±3 pixels each frame for 2 frames)
- Transitions use frame counters (fade over 18 frames @ 60 FPS = 0.3s)
- Speed progression uses gameState.elapsedSeconds (time-based, not frame-based)

## Acceptance criteria
1. HUD displays score, coins, XP, level, active power-ups, active skills
2. HUD updates in real-time on coin pickup, XP gain, level-up, power-up activation/expiry
3. Game-over screen shows final stats (score, XP, level) with accuracy
4. Game-over waits 3 seconds before accepting input (no accidental restart)
5. Restart Level button resets player position, tilemap, collectibles, power-ups (fresh level)
6. Back to Menu button returns to character select (preserves progression)
7. Next Level button appears if goal is reached (e.g., all coins collected)
8. Start screen displays title, play button, credits button
9. Character select shows unlocked skins, allows selection, shows level/XP
10. Screen shake triggers on enemy death (2-frame ±3px jitter)
11. Coin pickup spawns 5-8 particles, fade over 0.3s
12. Gem pickup spawns 8-12 particles, fade over 0.5s
13. Enemy death spawns dust puff (3-5 particles, white/gray)
14. Menu transitions fade to/from black (0.3s)
15. Speed increases from 1x to 2x over 120 seconds (scrolling applies to all entities)
16. Scrolling camera follows player; all entities move together

## Risks
1. **HUD clutter** - Displaying too many stats may clutter screen. Mitigation: use compact layout (single column, small font); prioritize most important stats (score, level).
2. **Game-over false restart** - If input delay is missed, player may accidentally restart. Mitigation: enforce 3-second input freeze; test on real hardware.
3. **Particle performance** - With 50+ collectibles per level and particles on each, may cause FPS drop. Mitigation: cap max concurrent particles to 50; remove oldest when limit reached.
4. **Screen shake alignment** - Jitter may cause player to miss precise platforming. Mitigation: keep jitter small (±3px); only apply to non-critical frames (not during jump input).
5. **Speed progression balance** - Ramping from 1x to 2x over 120s may be too fast or too slow. Mitigation: design levels with speed curve in mind; test and adjust formula.
6. **Scrolling level design** - Existing levels may have softlock zones with scrolling enabled. Mitigation: review all level designs; ensure no off-screen traps.

## Open questions
1. Should speed progression apply to player movement, or just camera scroll? (Assumption: camera scroll only; player input unchanged)
2. Does game-over screen show a "Next Level" button even if goal not reached? (Assumption: only show if all coins collected)
3. Should restart level reset player XP counter, or keep progress? (Assumption: keep XP progress; only reset level-specific state)
4. Can player pause during gameplay, or only at menu? (Assumption: no pause; deferred to future feature)
5. Should background animate (e.g., scrolling parallax), or static? (Assumption: static; parallax deferred to future polish)
