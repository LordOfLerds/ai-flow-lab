# G-0001

## Title
introduce reversible task lifecycle with archive semantics

## Priority
high

## Goal statement
I want the task domain to support a coherent archive lifecycle without jumping immediately into broad refactors.

## Constraints
- keep patches small and reviewable
- do not invent semantics without explicit documentation
- prefer docs/truth work before implementation if semantics are unclear

## Non-goals
- no persistence layer
- no UI overhaul
- no broad refactor

## Owner notes
We want a path that can later support unarchive, but not necessarily in the first patch.
